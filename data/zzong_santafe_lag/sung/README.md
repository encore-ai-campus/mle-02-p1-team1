# 캐스퍼 일렉트릭 매뉴얼 도우미

캐스퍼 일렉트릭 매뉴얼에 대해 질문하면, **Supabase 벡터 DB에서 관련 내용을 검색하고 OpenAI가 그 내용을 근거로 답변을 작성하는** Streamlit 앱입니다. e약은요 API 프로젝트와는 별개의 프로젝트입니다.

이 문서는 **Windows 11, VS Code, uv가 설치된 컴퓨터**를 기준으로 설명합니다. 처음 파일을 받은 사람은 1~6절을 순서대로 따라 하세요. 이미 팀 프로젝트에서 실행 중이라면 7절을 참고하세요.

## 1. 어떤 프로그램인가요?

```text
브라우저에서 질문 입력
  → 내 컴퓨터의 E5 모델이 질문을 숫자 벡터로 변환
  → Supabase 벡터 DB에서 관련 매뉴얼 청크 최대 5개 검색
  → 질문과 검색한 원문을 OpenAI에 전달
  → 답변과 검색 근거를 브라우저에 표시
```

- **청크**: 검색하기 좋게 나눈 매뉴얼의 작은 조각입니다.
- **임베딩**: 글의 의미를 숫자 목록으로 바꾸는 작업입니다. 질문 임베딩은 `intfloat/multilingual-e5-base` 모델을 사용하며 크기는 768입니다.
- **벡터 DB**: 질문과 의미가 가까운 매뉴얼 조각을 찾는 데 사용합니다.
- **LLM**: 검색한 원문을 읽고 사람이 이해하기 쉬운 답변을 만드는 언어 모델입니다. 현재 기본 설정은 `gpt-6-luna`입니다.
- **RAG**: 관련 자료를 검색한 뒤, 그 자료를 근거로 답변을 생성하는 전체 흐름입니다.

앱 실행 시 실제 Supabase와 OpenAI에 연결합니다. 검색 결과가 없으면 OpenAI를 호출하지 않고 검색 결과가 없다는 안내를 표시합니다.

## 2. 배포 전에 준비할 것

### 파일을 전달하는 사람이 확인할 사항

이 배포본은 **이미 매뉴얼 데이터가 준비된 Supabase DB에 연결하는 실행용 앱**입니다. 프로젝트에서 매뉴얼 청크와 임베딩을 각각 1,874개 생성했습니다. 받는 사람이 PDF부터 다시 처리할 필요는 없습니다.

배포자는 연결할 Supabase에 다음이 준비되어 있는지 확인해야 합니다.

| 항목 | 용도 |
| --- | --- |
| `manual_chunks` 테이블 | 매뉴얼 원문과 제목·페이지 등 저장 |
| `manual_embeddings` 테이블 | 청크에 대응하는 임베딩 저장 |
| `match_manual_chunks` 함수 | 질문 벡터로 관련 청크를 검색하는 DB 함수(RPC) |

검색 함수는 `query_embedding`, `match_count`, `filter_model`, `filter_version`을 받고, 앱에 필요한 `chunk_id`, `source_title`, `page_start`, `page_end`, `chunk_text`, `similarity`를 반환해야 합니다. 검색 대상 임베딩은 `intfloat/multilingual-e5-base`, 버전 `v1`, 크기 768과 일치해야 합니다.

**새 Supabase 프로젝트에 이 ZIP만 복사하면 데이터와 검색 함수가 자동으로 만들어지지는 않습니다.** 다른 DB를 쓰려면 기존 전처리·임베딩·DB 입력 작업과 검색 함수 설정을 별도로 진행해야 합니다. 처음 사용하는 팀원은 배포자에게 이미 준비된 DB의 연결 정보를 받으세요.

### 파일을 받는 사람에게 필요한 것

- Windows 11, VS Code, 설치된 uv
- 인터넷 연결: 라이브러리·임베딩 모델 다운로드 및 Supabase·OpenAI 연결에 필요합니다.
- 준비된 Supabase의 URL과 서버용 비밀 키
- OpenAI API 키와 해당 모델을 호출할 수 있는 계정 설정

실제 API 요청은 계정의 사용량과 비용에 반영될 수 있으므로 사용할 계정을 팀에서 정하세요. 서버용 비밀 키는 신뢰하는 팀원이 자신의 컴퓨터에서 실행하는 용도로 전달하세요.

## 3. 어떤 파일을 전달하나요?

`casper_streamlit.zip`에는 아래 파일이 들어 있습니다.

```text
casper_streamlit/
├─ README.md          ← 이 안내서
├─ pyproject.toml     ← 앱에 필요한 Python 라이브러리 목록
├─ .python-version    ← Python 3.12 사용 설정
├─ .env.example       ← 연결 정보 입력 양식(실제 키 없음)
├─ .gitignore         ← Git에서 제외할 파일 목록
└─ src/
   ├─ app.py          ← 질문 입력·답변·근거를 보여 주는 화면
   └─ rag.py          ← 질문 임베딩·DB 검색·답변 생성
```

실제 키를 담은 `.env`, 설치된 라이브러리 폴더 `.venv`, 모델 캐시, 노트북, PDF는 이 실행용 ZIP에 포함하지 않습니다. 연결 정보는 공개 저장소나 일반 배포 ZIP에 넣지 말고 별도로 전달하세요.

## 4. 처음 받은 컴퓨터에서 환경 설정하기

### 4-1. 압축을 풀고 VS Code에서 폴더 열기

1. Windows 탐색기에서 ZIP을 우클릭하고 **모두 압축 풀기**를 선택합니다.
2. 예를 들어 `C:\casper_streamlit`에 파일을 둡니다. 이 폴더를 열었을 때 `README.md`, `pyproject.toml`, `src`가 바로 보여야 합니다.
3. VS Code에서 **파일 → 폴더 열기**를 선택하고 해당 폴더를 엽니다.
4. **터미널 → 새 터미널**을 선택합니다. 터미널은 **PowerShell**을 사용합니다.

아래 예시는 폴더가 `C:\casper_streamlit`인 경우입니다. 다른 곳에 풀었다면 첫 줄의 경로를 자신의 폴더로 바꾸세요. 공백이 있는 경로도 따옴표로 감싸면 됩니다.

```powershell
cd "C:\casper_streamlit"
uv --version
```

uv 버전이 표시되면 준비되었습니다. `uv`를 찾을 수 없다는 메시지가 나오면 VS Code를 완전히 닫았다가 다시 열어 확인하세요.

### 4-2. Python과 라이브러리 설치

같은 터미널에서 아래 명령을 **한 줄씩** 실행하고, 각 작업이 끝난 뒤 다음 줄을 실행하세요.

```powershell
uv python install 3.12
uv sync
```

| 명령 | 하는 일 |
| --- | --- |
| `uv python install 3.12` | 앱에서 사용할 Python 3.12를 준비합니다. 이미 준비되어 있으면 재사용합니다. |
| `uv sync` | `pyproject.toml`을 읽고 `.venv` 가상환경과 필요한 라이브러리를 준비합니다. |

**가상환경**은 이 앱에 필요한 Python과 라이브러리를 관리하는 공간입니다. 이 독립 배포 폴더에서는 `.venv`가 `C:\casper_streamlit\.venv`에 생깁니다. 별도로 `uv init`, `uv venv`, 가상환경 활성화 명령을 실행할 필요는 없습니다. 이후 `uv run`이 이 환경으로 프로그램을 실행합니다. [uv 공식 프로젝트 안내](https://docs.astral.sh/uv/guides/projects/)

첫 설치에는 모델 실행에 필요한 PyTorch 등도 포함되어 다운로드가 오래 걸릴 수 있습니다. 설치 중에는 터미널을 닫지 마세요. 완료되어 입력할 수 있는 상태로 돌아오면 다음 단계로 넘어갑니다.

이 배포본은 직접 사용하는 라이브러리 버전을 지정하지만 전체 의존성 버전을 고정하는 `uv.lock`은 포함하지 않습니다. 첫 `uv sync`에서 생성됩니다. 팀에서 동일한 환경을 유지하려면 정상 실행을 확인한 뒤 이 파일도 함께 관리하세요.

### 4-3. `.env` 파일 만들기

`.env`는 DB 주소와 API 키를 저장하는 **파일**입니다. 폴더가 아닙니다.

VS Code 왼쪽 파일 목록에서 `.env.example`을 복사하고, 같은 위치에 `.env`라는 이름으로 붙여 넣으세요. 또는 아래 명령을 한 번 실행해도 됩니다. **이미 `.env`가 있다면 덮어쓰지 말고 기존 파일을 사용하세요.**

```powershell
Copy-Item -LiteralPath ".env.example" -Destination ".env"
```

`.env`를 열어 오른쪽의 예시 값을 실제 연결 정보로 바꾸고 저장합니다.

```dotenv
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SECRET_KEY=your-supabase-secret-key
OPENAI_API_KEY=your-openai-api-key
OPENAI_MODEL=gpt-6-luna
```

| 항목 | 넣을 값 |
| --- | --- |
| `SUPABASE_URL` | 매뉴얼 데이터가 저장된 Supabase 프로젝트의 URL |
| `SUPABASE_SECRET_KEY` | 그 프로젝트의 서버용 비밀 키. 공개용 키와 혼동하지 마세요. |
| `OPENAI_API_KEY` | OpenAI API 요청에 사용할 실제 키 |
| `OPENAI_MODEL` | 답변 생성 모델 이름. 우선 전달받은 설정을 사용하세요. |

키에 꺾쇠괄호를 붙이거나 설명을 덧붙이지 마세요. `.env.txt`로 저장되지 않았는지도 확인하세요. `.env`는 `src` 안이 아니라 **`pyproject.toml`과 같은 폴더**에 있어야 합니다.

```text
C:\casper_streamlit\
├─ .env
├─ pyproject.toml
└─ src\
   ├─ app.py
   └─ rag.py
```

앱은 `rag.py`의 한 단계 위 폴더에서 `.env`를 읽습니다. 같은 이름의 Windows 환경변수가 이미 설정되어 있으면 환경변수 값이 우선합니다.

### 4-4. VS Code의 Python 환경 선택(선택 사항)

터미널에서 앱을 실행하는 데는 노트북의 **Select Kernel**이 필요하지 않습니다. 코드 편집 시 Python 환경을 맞추려면 VS Code의 Python 확장을 설치하고 `Ctrl+Shift+P` → **Python: Select Interpreter**에서 `.venv\Scripts\python.exe`를 선택하세요.

## 5. 앱 실행하기

### 시작

VS Code 터미널에서 앱 폴더로 이동한 상태로 실행합니다.

```powershell
cd "C:\casper_streamlit"
uv run streamlit run src/app.py
```

브라우저가 자동으로 열리지 않으면 터미널의 **Local URL**을 클릭하세요. 기본 주소는 [http://localhost:8501](http://localhost:8501)입니다. `localhost`는 앱을 실행 중인 내 컴퓨터를 뜻합니다. [Streamlit 공식 실행 안내](https://docs.streamlit.io/develop/concepts/architecture/run-your-app)

화면이 열렸다면 다음 순서로 사용합니다.

1. 아래 질문 입력란에 질문을 입력하고 Enter를 누릅니다.
2. “매뉴얼을 검색하고 답변을 작성하고 있습니다…” 안내가 끝날 때까지 기다립니다.
3. 답변 아래 **매뉴얼 근거 확인**을 펼쳐 검색한 원문을 확인합니다.

첫 질문에서는 E5 모델 파일을 다운로드하고 메모리에 올리므로 이후 질문보다 오래 걸릴 수 있습니다. 앱이 켜져 있는 동안 모델을 재사용합니다. 화면이 처음 열리는 것만으로 DB와 OpenAI 연결 성공을 확인한 것은 아닙니다. 질문을 보내고 답변을 확인하세요.

### 종료와 다음 실행

종료하려면 앱을 실행한 터미널을 클릭하고 **Ctrl+C**를 누릅니다. 브라우저 탭만 닫으면 서버는 계속 실행될 수 있습니다.

다음에 사용할 때는 같은 폴더에서 아래 명령만 실행하면 됩니다.

```powershell
uv run streamlit run src/app.py
```

설치 명령과 `.env` 복사는 매번 반복하지 않습니다. `.env` 값을 바꿨다면 Ctrl+C로 종료하고 다시 실행하세요. 실행 중인 앱이 연결 설정을 캐시하기 때문입니다.

## 7. 기존 팀 프로젝트에서 실행하는 경우

이미 `C:\mle-02-p1-team1\src\casper_manual`에서 작업 중인 사람을 위한 방법입니다. **처음 받은 독립 배포 폴더의 설치 방법은 4절을 사용하세요.**

1. 배포본의 `src/app.py`와 `src/rag.py`를 기존 캐스퍼 프로젝트의 `src`에 둡니다.
2. `README.md`와 `.env.example`을 캐스퍼 프로젝트 루트에 둡니다.
3. 기존 `.env`와 기존 `pyproject.toml`을 유지합니다. 독립 배포용 `pyproject.toml`, `.python-version`, `.gitignore`로 기존 팀 설정을 덮어쓰지 마세요.

```powershell
cd "C:\mle-02-p1-team1\src\casper_manual"
uv sync --package casper-manual --no-install-workspace --inexact
uv run --no-sync streamlit run src/app.py
```

현재 팀 프로젝트의 `pyproject.toml`에는 `streamlit`, `openai`, `python-dotenv`, `sentence-transformers`, `supabase`가 등록되어 있습니다. 위 명령은 이를 설치한 뒤 앱을 실행합니다.

- `--no-install-workspace`: 팀 프로젝트 자체의 패키지 빌드를 건너뛰고 필요한 라이브러리를 설치합니다. 현재 파일 구성에서 패키지 빌드 오류를 피하는 데 사용합니다.
- `--package casper-manual`: 공유 환경에서 캐스퍼 프로젝트에 필요한 라이브러리를 설치 대상으로 지정합니다.
- `--inexact`: 공유 환경에 이미 설치된 다른 라이브러리도 유지합니다.
- `--no-sync`: 바로 앞에서 준비한 환경으로 실행합니다. 의존성을 수정했다면 먼저 설치 명령을 다시 실행하세요.

이 팀 저장소는 uv workspace를 사용하므로 `.venv`는 캐스퍼 폴더 안이 아니라 **`C:\mle-02-p1-team1\.venv`**에 생깁니다. workspace는 여러 프로젝트가 하나의 환경을 공유하는 구성입니다. [uv workspace 공식 안내](https://docs.astral.sh/uv/concepts/projects/workspaces/)

따라서 VS Code에서 Python 환경을 선택할 때도 이 루트의 `.venv\Scripts\python.exe`를 선택합니다. Jupyter 노트북 셀을 먼저 실행할 필요는 없습니다.

## 8. 문제가 생겼을 때

| 증상 | 확인·해결 방법 |
| --- | --- |
| `uv`를 찾을 수 없다고 나옴 | VS Code를 닫았다가 다시 열고 `uv --version`을 실행합니다. 계속 실패하면 uv 설치와 PATH 설정을 확인합니다. |
| `pyproject.toml`을 찾지 못함 | 터미널이 압축을 푼 앱 폴더인지 확인합니다. `Get-Location`으로 현재 위치를 확인하고 `cd`로 이동하세요. |
| `src/app.py`를 찾지 못함 | `src`가 바로 보이는 앱 폴더에서 실행했는지 확인합니다. 압축 해제 후 폴더가 한 번 더 중첩되었을 수 있습니다. |
| 라이브러리를 찾지 못함 | 독립 배포본은 `uv sync` 후 `uv run`으로 실행합니다. 기존 팀 프로젝트는 7절의 명령을 사용합니다. |
| 패키지 빌드 오류가 나옴 | 기존 팀 프로젝트라면 7절의 `--no-install-workspace`, `--no-sync` 명령을 사용합니다. |
| `.env`에 항목을 설정하라는 안내 | 파일 위치, 파일명이 `.env.txt`가 아닌지, 세 가지 필수 값이 채워졌는지 확인합니다. |
| “답변을 가져오지 못했습니다” | 인터넷 연결, Supabase URL·키, 검색 함수 존재 여부, OpenAI 키·모델 접근·사용 가능 상태를 배포자와 확인합니다. 이 문구만으로 어느 서비스가 실패했는지는 구분할 수 없습니다. |
| “검색 결과를 찾지 못했습니다” | DB에 데이터가 있는지, 임베딩 모델·버전이 코드의 검색 조건과 일치하는지 배포자가 확인합니다. |
| 첫 질문이 오래 걸림 | 모델 다운로드·로딩 중일 수 있습니다. 인터넷 연결과 터미널 출력을 확인하고 완료를 기다립니다. |
| 8501 포트를 사용할 수 없다고 나옴 | 기존 앱을 Ctrl+C로 종료하거나, 아래의 다른 포트 실행 명령을 사용합니다. |
| 설정을 고쳤는데 반영되지 않음 | 앱을 종료하고 다시 실행합니다. 동일 이름의 Windows 환경변수가 설정되어 있는지도 확인합니다. |

다른 포트로 실행할 때:

```powershell
uv run streamlit run src/app.py --server.port 8502
```

기존 팀 프로젝트에서는 `uv run` 뒤에 `--no-sync`를 추가합니다. 접속 주소도 [http://localhost:8502](http://localhost:8502)로 바뀝니다.

문제를 팀에 공유할 때는 수행한 명령과 오류 내용을 전달하세요. `.env` 전체나 실제 API 키는 메시지·스크린샷에 포함하지 마세요.

## 9. 현재 기능과 확인 범위

### 현재 기능

- 질문마다 새로 임베딩하고 Supabase에서 최대 5개 청크를 검색합니다.
- 검색 원문을 OpenAI에 전달해 답변을 생성합니다.
- 답변과 함께 검색 근거의 제목·페이지·청크 ID·유사도·원문을 보여 줍니다.
- 화면에 이전 질문과 답변을 유지하고 대화 지우기를 제공합니다.

### 사용 시 알아둘 점

- 이전 대화는 화면에만 표시됩니다. 후속 질문의 의미를 이전 대화에서 해석하는 기능은 없습니다. “그건 어떻게 해?”보다는 대상과 상황을 포함한 질문을 입력하세요.
- 기록은 영구 저장하지 않습니다. 새 세션이나 서버 재시작 후에도 유지되는 대화 저장 기능은 없습니다.
- 현재는 유사도가 낮은 검색 결과를 자동으로 제외하는 임계값이 없습니다. 검색 유사도는 정답 확률이 아닙니다.
- 인용 번호는 모델이 작성합니다. 모든 검색 결과가 답변에 사용되는 것은 아니며, 원문과 대조가 필요합니다.
- 표시하는 페이지는 DB에 저장된 범위입니다. 청크의 특정 문장이 그 범위 중 정확히 어느 페이지에 있는지까지 표시하지는 않습니다.
- 앱은 기존 데이터로 질문에 답하는 기능을 제공합니다. PDF 청킹·문서 임베딩 생성·DB 입력은 실행하지 않습니다.

### 전달 전 테스트와 실제 실행의 차이

**“전달 전 테스트에서 실제 DB·OpenAI 요청을 실행하지 않았다”는 말은 앱이 DB나 LLM을 사용하지 않는다는 뜻이 아닙니다.**

전달 전 자동 테스트에서는 외부 서비스 대신 테스트용 응답을 연결해 화면 시작, 질문 제출, 출처 원문 표시, 여러 답변 유지, 화면 재표시 시 중복 요청 방지, 오류 안내, 대화 지우기를 확인했습니다. 검색·답변 함수도 테스트용 클라이언트로 입력 처리와 근거 연결 등을 확인했습니다.

배포된 `rag.py`에는 이 테스트용 클라이언트가 들어 있지 않습니다. 실제 실행 시 `SentenceTransformer`, Supabase 클라이언트, OpenAI 클라이언트를 생성합니다. 질문에 대한 정상 답변과 검색 근거가 나오면 실제 검색과 답변 생성 흐름을 통과한 것입니다. 다만 화면이 열렸다는 사실만으로 외부 서비스 연결까지 확인되는 것은 아닙니다.

새 배포 폴더 전체를 다른 컴퓨터에서 처음 설치하는 과정과 모든 실제 질문의 답변 품질까지 검증한 것은 아닙니다. 배포 후에는 6절의 질문으로 자신의 환경에서 연결과 답변 근거를 확인하세요.
