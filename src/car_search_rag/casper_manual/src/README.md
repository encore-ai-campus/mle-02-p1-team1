# CASPER 매뉴얼 RAG · 프로젝트 산출물

캐스퍼 일렉트릭 사용설명서에서 질문에 필요한 근거를 찾아 답하는 RAG 프로젝트입니다. 데이터 준비부터 검색 품질 평가까지의 과정을 Streamlit 산출물 페이지로 제공합니다.

## 프로젝트 핵심

**의미 검색과 제목·본문 키워드 검색을 결합한 DB 검색 함수**가 답변에 사용할 근거를 선택합니다. 검색한 본문에 연결된 매뉴얼 그림도 답변에 활용할 수 있습니다.

```text
사용자 질문
  ↓ rag.py: 질문 임베딩 + 검색 단어 준비
DB 검색 함수: 벡터 후보 + 키워드 후보 → 순위 결합 → 근거 선택
  ↓ rag.py: 연결 이미지 조회 + 답변 입력 준비
LLM: 매뉴얼 본문·선택된 실제 그림을 참고해 답변
  ↓
답변 + 출처 + 관련 그림
```

전처리는 검색할 자료를 준비하고, 검색 함수는 근거를 고르며, LLM은 근거를 해석해 답합니다. 검색 함수만으로 전처리 누락이나 답변의 누락까지 모두 해결할 수는 없습니다.

## 화면 구성

| 페이지 | 내용 |
|---|---|
| 프로젝트 한눈에 | 전체 작업과 개선 과정 |
| 매뉴얼 질문하기 | 질문·답변·검색 근거·연결 그림 |
| 01 데이터·전처리 | 데이터 명세와 전처리 과정 |
| 02 데이터 분석 | 장별 분량·청크 길이·중복·통계·TF-IDF |
| 03 검색·답변 구조 | 적재·이관·검색·이미지 활용·개선 기록 |
| 04 검색 품질 평가 | 초기·1차·2차 평가와 실제 답변 |
| 05 최종 결과 요약 | 검색·답변 지표와 처리 시간 비교 |
| 06 DB 검색 함수 이해하기 | 쉬운 설명·단계별 탐색·가중치 체험 |

질문 화면의 표시 여부와 최초 화면은 `app2.py`에서 정합니다. 팀 산출물용 `app2.py`는 질문 화면을 메뉴에서 제외할 수 있습니다. 06 페이지의 체험은 가상 후보로 계산하며 실제 DB 설정을 바꾸거나 API를 호출하지 않습니다.

| 파일·폴더 | 역할 |
|---|---|
| `app2.py` | Streamlit 실행 파일과 메뉴 |
| `rag.py` | 질문 임베딩·DB 검색 호출·이미지 조회·답변 생성 |

`downloads/`의 ZIP은 앱 다운로드 버튼에서 사용하므로 압축된 상태로 유지합니다. `code/`에 SQL을 저장하거나 GitHub에 올리는 것만으로 DB 함수가 적용되지는 않습니다.

## 사용 기술

- 화면·표·메뉴: Streamlit
- 시각화: Streamlit의 `st.vega_lite_chart()`와 Vega-Lite
- 문장 임베딩: `intfloat/multilingual-e5-base` · 768차원
- 데이터 저장: Supabase PostgreSQL · pgvector
- 이미지 파일 저장: Supabase Storage
- 답변 생성: OpenAI API · 코드 기본 모델 `gpt-6-luna` (`OPENAI_MODEL`로 변경 가능)
- 디자인: CSS

Plotly는 사용하지 않습니다. 이 산출물 시각화를 위해 추가 차트 라이브러리를 설치할 필요는 없습니다.

## DB 검색 함수

기본 RPC 이름은 `match_manual_chunks_hybrid`입니다.

1. 청크와 임베딩을 `chunk_id`로 연결하고 모델·버전을 필터링합니다.
2. 의미가 가까운 청크와 제목·본문의 검색 단어가 일치하는 청크를 각각 찾습니다.
3. 기본적으로 각 경로에서 최대 50개 후보를 모읍니다.
4. 서로 다른 점수를 그대로 더하지 않고 각 목록의 순위를 가중 RRF 방식으로 합칩니다.
5. 기본 상위 5개 근거를 반환합니다.

초기 설정은 벡터 가중치 1, 키워드 가중치 2, 순위 상수 20입니다. 유사도는 정답 확률이 아니며 최종 순서는 `hybrid_score`로 정합니다. 질문 분해나 ReAct는 포함하지 않습니다.

팀 DB의 관련 테이블은 `casper_manual_chunks`, `casper_manual_embeddings`, `casper_manual_images`, `casper_manual_chunk_images`입니다. 개인 DB에서 텍스트 테이블이 `manual_chunks`, `manual_embeddings`라면 SQL의 대상 테이블명이 달라집니다. pgvector 확장 스키마도 DB별로 확인해야 합니다.

이미지 자체를 별도 벡터로 검색하는 구조는 아닙니다. 먼저 텍스트 청크를 찾고, 연결된 이미지 설명·OCR과 선택한 실제 그림을 답변 입력에 활용합니다. 관련 청크를 못 찾거나 이미지 연결이 없으면 그림도 빠질 수 있습니다.

## 로컬 실행

Python 3.12 이상과 uv가 준비된 환경에서, 이 폴더로 이동한 뒤 실행합니다.

```powershell
Set-Location 'C:\mle-02-p1-team1\src\car_search_rag\casper_manual'
uv sync
uv run streamlit run src/chatbot_project/app2.py
```

앱을 이 폴더에서 실행한다면 `.streamlit/secrets.toml`에 다음 설정을 넣을 수 있습니다.

```toml
SUPABASE_URL = "https://프로젝트ID.supabase.co"
SUPABASE_SECRET_KEY = "사용할 Supabase 키"
OPENAI_API_KEY = "사용할 OpenAI API 키"
# 선택: 기본 답변 모델을 바꿀 때 지정
OPENAI_MODEL = "gpt-6-luna"
```

`SUPABASE_URL`은 Supabase API 주소이며 DBeaver의 PostgreSQL pooler 주소가 아닙니다. 실제 키를 README나 GitHub에 올리지 마세요. 환경변수도 사용할 수 있습니다.

산출물 페이지는 함께 배포한 로컬 자료를 읽습니다. 질문 기능은 유효한 키, DB 검색 함수, 데이터와 이미지 접근 설정이 필요합니다. 질문 화면을 처음 열 때 임베딩 모델을 준비하므로 최초 로딩에 시간이 걸릴 수 있습니다.

## Streamlit 배포

팀 저장소를 직접 배포하는 경우의 실행 경로:

```text
Branch: main
Main file path: src/car_search_rag/casper_manual/src/chatbot_project/app2.py
```

개인 저장소의 실행 경로는 `src/chatbot_project/app2.py`입니다. 다른 팀 UI에 기능을 통합한 경우에는 해당 UI의 실행 파일을 사용합니다.

Cloud의 Secrets에도 같은 설정 이름을 등록합니다. `project_assets/`가 빠지면 산출물의 그래프·표·다운로드가 동작하지 않습니다. 변경 파일을 커밋·푸시하고 배포 화면에서 메뉴를 확인하세요. GitHub는 최신인데 메뉴가 이전 상태라면 앱 재시작(Reboot) 후 확인할 수 있습니다.

## 평가 결과

기존 30개 질문은 정상 18개, 답할 수 없는 질문 6개, 경계 사례 6개로 구성했습니다.

| 항목 | 초기 | 1차 · 이미지 연결 | 2차 · 검색 개선 |
|---|---:|---:|---:|
| 답변 충족 | 24/30 | 25/30 | 25/30 |
| 부분 충족 | 5 | 4 | 4 |
| 미충족 | 1 | 1 | 1 |
| 정답 근거 확보 Hit@5 | 20/23 | 20/23 | 22/23 |
| 필수 내용 근거 확보 | 46/50 | 46/50 | 48/50 |
| 평균 앱 처리 시간 | 3.93초 | 4.00초 | 6.72초 |

- **30개**는 전체 질문 수입니다.
- **23개**는 검색 근거 평가 대상 질문 수입니다. 답할 수 없는 질문 6개와 모호한 Q028은 제외했습니다.
- **50개**는 해당 질문들에서 확인할 필수 내용의 총합입니다. 한 질문에 배터리 규격·개수처럼 여러 필수 내용이 있을 수 있습니다.
- Hit@5는 필요한 근거를 상위 5개에서 하나 이상 찾은 질문 수입니다. 모든 필수 내용을 찾았다는 뜻은 아닙니다.
- 22/23과 48/50은 같은 검색 결과를 다른 단위로 센 값이며 합산하지 않습니다.

**결론:** 2차에서 검색 근거 확보는 개선됐지만, 1차 대비 최종 답변 충족 개수는 같고 평균 처리 시간은 늘었습니다. 제원 질문 3개에서는 정확한 답변을 별도로 확인했으며 기존 30개 점수에는 합산하지 않았습니다.

## 평가와 적용 상태의 범위

평가는 초기 2026-10-02 기록 및 이후 1차·2차 기록을 비교한 결과입니다. 2차 기록은 2026-10-06~07에 수집했습니다. 선정한 30개 사례이므로 전체 사용자 질문의 성공률이나 대규모 검증 결과로 일반화할 수 없습니다.

서로 다른 시점의 실행 비교이며 DB·모델·네트워크 조건을 통제한 실험은 아닙니다. 변화의 원인을 검색 함수 하나로 단정하지 않습니다. 개인 앱에서는 06 메뉴 표시를 확인했습니다. 팀 DB의 최신 함수 적용 및 팀 배포 화면의 최신 페이지 반영 여부는 별도 확인이 필요합니다.

남은 과제는 오타·복합 질문의 검색 누락, 답변의 조건 누락·상황 확인 행동, 표 전처리 및 이미지 연결 품질 점검입니다.
