임베딩은 답변 글을 만드는 작업이 아닙니다. 글을 숫자로 바꿔 비슷한 근거를 찾는 작업입니다. 문서와 질문은 반드시 같은 모델·차원으로 바꿔야 합니다. 그림은 사람이 작성한 설명 글을 임베딩하며, 이미지 픽셀을 임베딩하는 모델은 아닙니다.

기존 청크는 로컬 토크나이저의 128토큰 한도에 맞춰 나뉜 글입니다. 새 모델은 더 긴 입력을 받을 수 있지만 이번에는 청크를 합치지 않았습니다. 모델 변경 효과만 비교하기 위해서입니다. OpenAI 토큰 계산으로 가장 긴 기존 입력은 321토큰, 전체는 440,038토큰입니다.

## 진행 순서와 실행 파일

이미 이번 실행에서 전체 임베딩과 DB 저장을 완료했습니다. 아래 명령은 작업 구조를 이해하거나 재개할 때 사용합니다. 처음부터 다시 돌릴 필요는 없습니다.

프로젝트 폴더 `C:\mle-02-p1-team1`의 PowerShell에서:

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -m car_search_rag.zzong_santafe_lag.openai_migration prepare
.\.venv\Scripts\python.exe -m car_search_rag.zzong_santafe_lag.openai_migration sample
.\.venv\Scripts\python.exe -m car_search_rag.zzong_santafe_lag.openai_migration embed
.\.venv\Scripts\python.exe -m car_search_rag.zzong_santafe_lag.openai_migration save
```

1. `prepare`: DB 읽기·토큰 계산·비용 추정. 임베딩 API 호출 없음.
2. `sample`: 첫 16개 API 임베딩. 기존 성공 파일이 있으면 재사용.
3. `embed`: 나머지를 64개씩 API 처리. 성공 구간마다 개인 파일에 저장.
4. `save`: 별도 DB 테이블에 추가 → 읽어서 대조 → 완료 상태 설정.

`openai_embedding.py`는 LangChain의 OpenAIEmbeddings 연결, `openai_migration.py`는 전환 단계, `openai_search_service.py`는 새 벡터 검색, `openai_comparison.py`는 기존 30문항 비교를 담당합니다. SQL은 개인 mapper와 `db/06_openai_vectors.sql.txt`에 분리했습니다. 기존 SQL Mapper 실행 방식도 유지합니다.

중간 저장과 결과는 `C:\mle-02-p1-team1\data\zzong_santafe_lag\openai_embeddings`에 있습니다. API 키는 저장하지 않습니다. 자동 API 재시도는 0회이며, 실패한 요청의 서버 처리 여부가 불명확하면 재개 시 비용이 추가될 수 있습니다.

## 챗봇에서 사용하기

기존 `run_app.bat`로 화면 서버를 다시 실행하세요. 파일 감시를 꺼둔 상태여서 코드 변경은 서버 재시작 후 반영됩니다.

화면 왼쪽의 **검색에 사용할 모델 → OpenAI**를 선택하면 새 벡터를 사용합니다. **기존 로컬**을 선택하면 이전 모델로 비교할 수 있습니다. 모델을 바꾸면 현재 브라우저의 질문 기록만 초기화합니다. DB 결과는 지우지 않습니다.

검색 버튼은 질문 임베딩 API, 답변 생성 버튼은 gpt-6-luna 생성 API를 호출합니다. 별도 비용이며, PDF 밖 리콜·실제 차량 진단 요청은 검색 전에 차단합니다. 미검토 근거는 생성하지 않습니다. 그림 픽셀을 모델에 보냈다고 표현하지 않습니다.

## 검색 비교와 Precision

### 이번 실행 결과

| 같은 고정 30문항 | 기존 로컬 | OpenAI |
|---|---:|---:|
| Hit@5 | 1.000 | 1.000 |
| MRR@5 | 0.956 | 0.939 |
| Precision@5_expected_ids (보조값) | 0.200 | 0.200 |

기대 출처의 첫 순위가 달라진 질문은 Q26(엔진 오일 첨가제) 한 개입니다. 기존 PDF 43쪽 각주 근거가 로컬 1순위, OpenAI 2순위였고, OpenAI 1순위는 PDF 706·707쪽의 '엔진 오일 및 필터의 교체' 후보였습니다. 정답 ID와 다른 후보라는 이유만으로 내용이 틀렸다고 단정하지 않습니다. 미검토 원문은 기존 답변 보류·선택 규칙을 적용합니다. 이번 고정 평가에서는 OpenAI가 더 우수하다는 근거가 없습니다.

두 모델을 매 질문마다 순서대로 조회한 비교 실행은 **약 541초(9분)**였습니다. 이는 API 임베딩 자체 시간과 다릅니다. 전체 문서 임베딩 API 구간은 표본 약 3.1초 + 나머지 약 14.6초였으며 DB 조회·연결 준비·저장·평가는 별도입니다. 모든 환경에서 같은 시간이 걸린다는 의미는 아닙니다.

### 근거·보류·그림 연결 확인

기존 10문항의 상태·출처·문구·그림 연결·생성 준비 조건을 OpenAI 검색으로 확인했습니다. 기존 조건 기준은 **9/10**입니다. A10은 PDF 33쪽 미러 그림이 미업로드 상태일 때의 '표시 보류' 조건인데, 해당 그림은 10월 3일에 업로드 완료돼 지금은 연결된 그림 1개를 반환합니다.

기존 결과를 보존하고, A10을 'PDF 33쪽 그림 1개 연결'로 갱신한 **업로드 완료 후 평가 v2**에서 같은 저장 답변을 다시 채점해 **10/10**을 확인했습니다. 기대 조건 변경 항목·이유·원래 질문 식별값·새 식별값을 함께 남겼습니다. 추가 API 호출 없이 재채점했으며 모든 질문을 새로 실행한 결과와 구분합니다.

PDF 밖 리콜·실제 차량 진단 질문은 검색하지 않았고, 스마트 테일게이트 미검토 근거는 생성 준비도 False였습니다. 생성 API 호출은 0회입니다. 이것은 생성 답변의 의미 정확도나 실제 브라우저의 이미지 픽셀 표시 확인이 아닙니다. 화면 서버를 재시작한 뒤 실제 화면도 확인하세요.

청킹·TF-IDF·질문 목적 규칙·구체 표현 규칙을 같게 두고 임베딩 모델만 비교합니다. 기존 고정 질문 30개를 재사용하므로 새로운 질문에 대한 독립 평가가 아닙니다.

Hit@5는 상위 5개에서 기대 출처를 한 번이라도 찾은 질문 비율, MRR@5는 기대 출처의 첫 순위가 얼마나 높은지 나타냅니다.

이번 `Precision@5_expected_ids`는 **상위 5개 후보 중 기존 정답 ID가 들어 있는 후보 비율**입니다. PDF 110쪽 버클처럼 다른 유효한 근거가 정답 목록에 등록되지 않은 경우가 있습니다. 따라서 전체 관련 근거를 사람에게 판정받은 정식 Precision@5와 구분합니다. 다음 평가에서는 질문별로 상위 후보 원문을 읽어 관련/무관을 표시한 뒤 두 모델에 같은 판정표를 적용해야 합니다.

## 비용과 용량

일반 API 입력 $0.02/백만 토큰 기준, 문서 440,038토큰은 약 **$0.00880076**입니다. 질문 임베딩·답변 생성 비용과 실제 청구액은 별도입니다. [OpenAI 공식 모델 가격](https://developers.openai.com/api/docs/models/text-embedding-3-small).

새 DB 테이블·색인·TOAST 합계는 **18,972,672바이트(18.97MB)**입니다. 벡터 배열 자체보다 PostgreSQL 저장 영역이 더 큽니다. Storage 그림 용량은 32,406,621바이트로 유지합니다. WAL·공통 DB 영역·다른 팀원 자료·요금 청구량은 이 개인 측정에서 제외합니다.

전체 개인 DB 실측은 35,479,552바이트(35.48MB), 기존 Storage와 합계는 67,886,173바이트(67.89MB)입니다. 물리 저장 공간은 실행·유지관리 시 달라질 수 있으며 원문 행의 변경 여부는 공간 수치가 아니라 내용 식별값으로 별도 대조했습니다.
