이 문서는 **수정 전 평가 기록**입니다. 이후 사용자 승인으로 보완하고 다시 확인한 결과는 [답변 보완 안내](./answer_fix_guide.md)와 [29번 노트북](./29_answer_selection_fix.ipynb)에 따로 기록했습니다. 아래 실패 결과와 원래 판정표는 보존합니다.

## 이번에 확인한 내용

기존 30문항과 다른 **새 질문 10개**를 먼저 정한 뒤, 같은 청크·검색 규칙으로 로컬 임베딩과 OpenAI 임베딩을 비교했습니다. 후보의 원문 내용을 읽어 질문에 직접 답할 자료인지 판정했습니다. 답변 생성은 사전에 정한 3문항만 실행했습니다.

**검색은 직접 근거를 찾았지만, 답변에 쓸 자료를 고르는 과정과 생성 결과 검사에서 보완할 부분이 나왔습니다.** 이 평가에서 챗봇의 검색·답변 코드를 수정하지 않았습니다.

## 1. 검색 점수

| 항목 | 기존 로컬 모델 | OpenAI 모델 |
|---|---:|---:|
| 모델 | jhgan/ko-sroberta-multitask-mrl | text-embedding-3-small |
| 차원 | 768 | 1536 |
| 새 질문 수 | 10 | 10 |
| Hit@5 | 100% | 100% |
| Precision@5 | 36% | 36% |
| MRR@5 | 0.95 | 0.95 |

- **Hit@5 100%**: 10개 질문 모두 검색 후보 5개 안에서 직접 근거를 하나 이상 찾았습니다.
- **Precision@5 36%**: 모델별 후보 총 50개 중 18개가 질문에 직접 답할 내용을 포함했습니다. 평균적으로 후보 5개 중 1.8개입니다. 나머지는 비슷한 주제이거나 부품 위치·목차·참조 쪽수만 있는 자료였습니다.
- **MRR@5 0.95**: 첫 직접 근거가 9문항은 1위, 1문항은 2위였습니다.

36%는 최종 답변의 정답률을 뜻하지 않습니다. 상위 후보의 관련성 점수입니다. 두 모델의 점수가 같으므로 이번 표본에서 OpenAI 모델이 더 우수하다고 판단하지 않습니다.

**사람의 교차 검토 전 잠정값입니다.** Codex가 두 검색 결과의 후보 100건을 질문별 원문 묶음 61개로 중복 제거해 판정했습니다. 같은 묶음은 양쪽 모델에 같은 판정을 적용했습니다. 판정에는 관련 여부, 이유, 관련 판정의 원문 인용을 남겼습니다. 일부 요청의 직접 근거도 관련 자료로 셌습니다.

예를 들어 헤드레스트 질문에서는 뒷좌석 설명에도 귀 상단 위치 기준이 있어 부분 근거로 셌지만, 그것만으로 운전석의 모든 조건을 설명할 수 있다고 보지는 않습니다. 사람의 검토에서 이런 경계를 다시 확인해야 합니다. 후보 판정표에는 모델·순위를 숨겼지만, 이전 검색 결과를 본 상태이므로 완전한 눈가림 평가라고 주장하지 않습니다.

이전 30문항의 정답 ID 기준 보조 Precision 20%와는 질문·판정 방법이 다릅니다. **20%에서 36%로 개선됐다는 비교는 하지 않습니다.** 이번 질문은 이미 검토한 일부 주제에서 만든 합성 질문이며, 전체 779쪽의 독립 사용자 평가가 아닙니다.

## 2. 실제 생성 답변 3문항

생성 모델은 기존 **gpt-6-luna**, 추론 설정은 `none`입니다. 검색해 둔 OpenAI 근거를 사용했고, 기대 정답을 생성 모델에 전달하지 않았습니다.

| 질문 | 확인한 결과 | 판단 |
|---|---|---|
| N01 엔진이 뜨거울 때 냉각수 보조 탱크 캡을 열어도 되는가 | 차가운 엔진에서 점검하고, 뜨거운 캡을 열면 냉각수 분출·화상 위험이 있다고 답함. PDF 52쪽 인용 | 생성 완료. 요청한 조건·위험이 근거와 일치 |
| N05 좌석·스티어링 휠·미러를 주행 중 조절해도 되는가 | 올바른 조작 지침은 2위에 있었으나 1위의 차량 내부 위치 안내도를 선택. 생성 검사에서 ValueError 후 위치 안내도 발췌로 돌아감 | 질문에 맞는 답변 실패. 근거 선택 개선 필요 |
| N08 표에 나온 연료 용량·종류 | 선택 근거에 67 ℓ·무연 휘발유가 있으나 생성 검사에서 ValueError 후 원문 발췌로 돌아감 | 생성 실패. 발췌에는 요청 정보가 남아 있음 |

**3회 중 1회 생성 완료, 2회 발췌 전환**입니다. 이를 챗봇 전체 정확도 33% 또는 발췌 포함 성공 100%로 표현하지 않습니다. N05는 발췌 자체도 질문에 직접 답하지 못합니다.

N08에서는 연료 표에 더해 오일 관련 각주도 함께 전달됐습니다. 현재 생성 검사는 전달한 모든 출처를 인용하도록 요구합니다. 이 규칙이 불필요한 각주 때문에 실패했을 가능성은 있지만, 실패 당시 모델 원문과 상세 검사 사유를 저장하지 않아 **ValueError의 정확한 원인은 확정할 수 없습니다.**

## 3. 다음 수정 제안 — 적용 전 설명

1. **답변 근거 선택 보완:** 위치 질문에는 안내도를, 조작·허용 여부 질문에는 그 조건과 지시 문장이 있는 검토된 자료를 우선 선택합니다. 특정 질문만 예외 처리하는 방식은 피하고 기존 위치 검색도 함께 확인합니다. N05에서 찾은 정확한 조작 지침을 답변에 연결하는 것이 목표입니다.
2. **생성 검사 실패 기록 보완:** 인증 정보가 없는 검사 사유와 생성 결과를 개인 보고서에 남겨 형식 오류·답변 보류·출처 검사 실패를 구분합니다. N08을 진단한 뒤, 실제 답변에 필요한 출처와 필수 각주를 함께 사용하는 규칙을 검토합니다. 모든 인용 검사를 일괄 해제하지 않습니다.
3. **수정 후 같은 자료로 재비교:** 기존 결과와 판정표를 보존하고 새 결과를 별도 저장합니다. 이번 10문항과 이전 위치·표·복합 질문·미검토/PDF 밖 보류 항목을 확인합니다. 새로 생성할 때는 필요한 문항만 호출합니다.

위 세 가지는 제안이며 아직 챗봇에 적용하지 않았습니다. 자료의 검토 상태를 임의로 바꾸지 않았습니다.

## 5. 재실행 방법과 사용량

이미 결과가 있으므로 지금은 28번 노트북으로 읽기만 하면 됩니다. 평가 도구를 실행해야 할 때는 프로젝트 루트 PowerShell에서:

```powershell
$env:PYTHONPATH = 'src'
# 저장된 판정표로 점수만 다시 계산합니다. API 호출 없음.
.\.venv\Scripts\python.exe -m car_search_rag.zzong_santafe_lag.fresh_evaluation score
```

단계는 `prepare` → `collect` → 후보 원문 판정 → `labels` → `score` → `generate`입니다. `labels`는 `fresh_relevance_review_20261005.json`을 읽어 후보 식별값에 연결하고 관련 판정의 인용문을 대조합니다. 새 후보는 사람이/검토자가 읽고 판정표를 먼저 작성해야 합니다. 미판정 후보를 임의로 채점하지 않습니다. 사람의 교차 검토 결과를 반영할 때는 원래 결과를 보존한 별도 평가 버전이 필요합니다.

`collect`는 성공한 검색 결과를 재사용합니다. `generate`는 시작 기록이 남은 문항을 자동 재호출하지 않습니다. 현재 도구는 이번에 고정한 평가용이므로 새 질문 평가 버전은 준비 코드를 먼저 검토해야 합니다.

이번 실제 사용량:

- 로컬 질문 검색 10회, OpenAI 질문 임베딩 10회. 검색 수집 시간 약 **218초(3분 38초)**. 문서 재임베딩 없음.
- 답변 생성 API 시도 **3회**, 합계 **3,854토큰**: 입력 3,666·출력 188. 발췌로 돌아간 2회도 호출 비용이 발생합니다.
- 별도 판정 모델 API 호출 0회. 이번 평가에서 DB 쓰기·Storage 업로드 0회.

이 수치는 이번 새 질문 평가에 한하며 이전 문서 임베딩·30문항 비교·화면 확인 사용량은 별도입니다. 다른 팀원 파일이나 DB 자료는 변경하지 않았습니다.
