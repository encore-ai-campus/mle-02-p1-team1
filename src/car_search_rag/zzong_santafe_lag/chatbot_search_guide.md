# 싼타페 챗봇과 검색기 이해하기

싼타페 HEV 설명서에서 관련 자료를 찾고, 원문 검토 상태와 질문 적합성을 확인한 뒤 출처·그림과 함께 설명하는 챗봇입니다. 자료 준비, 검색, 근거 선택, 답변 생성, 화면 표시는 각각 역할이 나뉩니다.

## 자료 준비와 저장

| 구성 | 쉬운 설명 | 역할 |
|---|---|---|
| 주제 자료인 부모 | 한 기능의 전체 설명 묶음 | 조건·경고·각주와 전체 문맥 보관 |
| 검색 조각인 청크 | 설명을 짧게 나눈 부분 | 질문과 가까운 내용을 찾기 |
| 임베딩 | 글의 의미를 표현한 숫자 목록 | 질문과 설명서의 유사도 비교 |
| DB | 글과 검색용 숫자 보관함 | 본문·청크·벡터·쪽수·검토 상태·그림 연결 저장 |
| Storage | 그림 파일 보관함 | 설명서에서 추출한 그림 저장 |
| GitHub | 코드와 작업 기록 보관함 | 코드·평가·대시보드 자료·검토 버전 선택 정보 공유 |

설명서의 벡터는 미리 계산합니다. 질문할 때는 질문만 같은 모델로 벡터로 바꿉니다. 검색은 짧은 조각으로 하고, 답변 근거에는 부모 설명과 필수 연결 문맥을 가져옵니다.

현재 저장된 분석 기준은 PDF 779쪽, 부모 자료 527개, 검색 청크 2,224개, 연결된 고유 그림 864개입니다. 검토된 부모는 33개, 미검토 부모는 494개입니다. 검토 주체는 Codex이며 사용자 원문 확인 완료 비율이나 정답률을 뜻하지 않습니다.

## 질문에서 답변까지

1. 질문이 모호하면 어떤 부품·상황인지 다시 묻습니다.
2. 명확한 용어와 공백을 정리합니다. 숫자·단위·부정·상황 조건은 유지합니다.
3. 질문을 임베딩하고 저장된 설명서 조각을 검색합니다.
4. 후보의 전체 본문, 필수 각주·주의사항, 그림 연결을 복원합니다.
5. 질문 적합성과 본문·필수 문맥의 검토 상태를 확인합니다.
6. 근거가 확보되면 원문 발췌·출처·그림을 표시하고, 부족하거나 미검토이면 보류합니다.
7. 사용자가 답변 정리를 요청하면 AI가 선택된 근거로 문장을 작성합니다. 형식·출처 검사 실패 시 발췌를 유지합니다.

검색용 기본 모델은 text-embedding-3-small, 답변 작성 모델의 현재 코드 설정은 gpt-6-luna입니다. 기존 로컬 검색 모델은 비교·검증용으로 유지합니다. 생성 모델은 그림 픽셀을 받지 않으며 본문과 검토된 그림 설명을 사용합니다.

## 검색 점수 계산

예시 질문은 “스마트 키 원격 시동은 어떻게 사용하나요?”입니다.

### 의미와 글자 일치

- 의미 점수: 질문과 설명서 조각의 벡터를 비교합니다. 정규화된 벡터의 내적으로 코사인 유사도를 계산합니다.
- 글자 점수: 공백을 정리한 글에서 연속된 글자 2~4개를 TF-IDF로 비교합니다. 여러 자료에 흔한 표현보다 자료를 구별하는 표현의 영향이 커집니다.
- 일반 설명 조각의 기본 점수는 `0.5 × 의미 점수 + 0.5 × 글자 점수`입니다.

같은 부모의 조각들 중 결합 점수가 가장 높은 조각을 그 부모의 대표 점수로 사용합니다. 긴 설명에 조각이 많다는 이유만으로 점수를 모두 더하지 않습니다.

위치 안내도는 부품 번호별 이름을 별도로 비교합니다. 부모의 최고 의미 점수와 부품 이름의 글자 점수를 결합한 값이 더 높으면 해당 값을 사용합니다.

### 구체 표현 보너스

질문에서 추출한 단어·이웃한 두 단어 표현이 원문에 실제로 있고, 전체 자료에서 드문 표현이면 최대 0.15의 보너스를 줍니다. 포함 관계인 표현을 중복 계산하지 않습니다. 검토 상태·평가 정답 ID·페이지 번호는 보너스 계산에 사용하지 않습니다.

### 질문 목적에 따른 후보 우선순위

| 질문 | 먼저 배치하는 자료 |
|---|---|
| 부품이 어디 있는지 | 위치 안내도 |
| 용량·규격·각주 | 표와 각주가 있는 자료 |
| 사용·조작·주의·증상 | 설명 자료 |
| 유형을 구별하기 어려운 질문 | 전체 자료 |

이 구분은 직접 작성한 표현 규칙입니다. 필요한 유형의 후보가 부족하면 전체 후보로 보충합니다. 특정 질문의 정답을 찾아주는 범용 의미 분석기는 아닙니다.

현재 기본 전체 검색은 DB에서 저장된 글·벡터를 읽고 Python에서 점수와 순위를 계산합니다. BM25, RRF, CrossEncoder, LLM 재정렬은 이 싼타페 기본 경로에 연결하지 않았습니다.

## 검색 후보와 답변 근거의 차이

검색기는 관련 후보를 정렬합니다. 이후 답변 서비스가 질문 단어, 조작 설명 유무, 증상과 제목의 관계, 원문 및 필수 문맥의 검토 상태를 확인합니다.

조작·증상 질문은 조건을 통과한 자료 중 주요 질문 단어가 더 많이 일치하는 근거를 우선합니다. 다른 질문은 적합한 후보의 기존 순서를 유지합니다. 그래서 검색 1위와 최종 근거가 달라질 수 있습니다.

기본 화면에서는 상위 5개 근거 묶음을 먼저 확인합니다. 근거 부족으로 판정된 경우에만 같은 검색의 최대 10개 후보까지 확인합니다. 추가 질문 임베딩이나 DB 검색은 하지 않습니다. 미검토 자료로 인한 보류는 이 확장으로 우회하지 않습니다.

관련 자료 검색, 질문에 맞는 근거 선택, 생성 답변의 정확성은 각각 따로 평가해야 합니다. 높은 점수나 검토 완료 표시가 질문의 정답을 보증하지 않습니다.

## 최근 보완과 남은 문제

- 초안 8개를 원문·그림과 대조하고 별도 검토 버전으로 반영했습니다. 기존 원문과 이전 검토 자료의 벡터는 보존했습니다.
- 새 청크 68개를 만들었습니다. 누적 검토 버전은 부모 13개·청크 96개입니다.
- 기존 질문 16개의 기대 출처 선택은 0/16에서 10/16으로 변했습니다. 기존 자료 회귀 질문 3/3을 유지했습니다.
- 실제 DB 경로에서 선루프 초기화·원격 시동·메모리 초기화 3문항의 검색과 생성을 확인했습니다. 생성 성공은 의미 정확도 점수가 아닙니다.
- 일상 표현의 규칙 누락, 일부 단어만 맞는 무관한 근거 선택, 미검토 자료의 답변 보류가 남아 있습니다.
- 명시적인 원문·그림 후속 요청은 직전 결과를 재사용합니다. 일반적인 모든 대화의 생략된 대상을 자동 추론하는 기능은 아닙니다.

## 화면과 배포

챗봇은 질문·근거·출처·그림을 표시합니다. 대시보드는 저장된 집계·평가를 표시하고, 작업 Document는 설계 이유·구현·실험 기록을 보여줍니다. 대시보드와 작업 Document를 여는 것만으로 DB·검색·생성 API를 호출하지 않습니다.

로컬 코드, GitHub 코드, 배포 서버의 실행 상태는 각각 확인해야 합니다. GitHub 푸시 성공과 배포 서버의 정상 응답은 별도 확인 항목입니다. 배포 확인 결과는 source_reviews/20261007_batch2/deployment_check.json에 기록합니다.

- app.py: 개인 화면과 공통 앱용 싼타페 연결
