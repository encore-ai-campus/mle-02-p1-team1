## 2. 새 표현에서 발견한 문제

| 질문 | 수정 전 근거 선택 | 원인과 보완 |
|---|---|---|
| 차량 내부 I 그림에서 지문 인증 기능에 붙은 번호 | 차대번호 자료 | 그림 번호 표현을 기능 설명으로 분류했고, '번호'의 단어 일치가 다른 자료를 허용했습니다. 그림 번호의 목적을 구별하고 일반 단어를 근거 선택 단어에서 제외했습니다. |
| 스티어링 휠과 미러 위치는 출발 전에 맞추나요 | 위치 안내도 | '위치'만 보고 안내도를 우선했습니다. 조절할 시점을 묻는 표현은 조작 지침을 찾도록 했습니다. |

`question_intent.py`에서 검색과 답변 선택이 같은 작은 한국어 규칙을 사용합니다. 질문별 정답·쪽수·ID를 운영 검색에 넣지 않았습니다. 규칙 방식의 한계가 있으므로 모든 한국어 표현에 대한 의미 판정으로 설명하지 않습니다.

수정 전 OpenAI 10문항의 기대 ID Hit@5는 80%, MRR@5는 0.62입니다. 후보 내용을 대조한 잠정 Hit@5는 80%, MRR@5는 0.72이며, Precision@5는 **22~24%**입니다. 50개 후보 중 직접 관련 11개, 경계 사례 1개를 따로 남겼습니다. 클러스터 질문의 일반 연료 점검 표를 관련으로 볼지는 사람 판정이 필요합니다.

이 평가의 문항은 확인한 일부 주제의 새 표현입니다. 이전 10문항의 36%와 문항이 달라 성능이 하락했다고 단정할 수 없습니다. 로컬은 3문항만 진단했으므로 모델 간 우위 비교에 쓰지 않습니다. 생성 API를 호출하지 않은 이 10문항의 결과를 생성 답변 정확도로 표시하지 않습니다.

## 4. DB 저장 구조를 왜 추가하나요?

기존 부모 527개·청크 2,213개·그림 864개를 다시 복제하면 용량이 늘고 이전 실험을 재현하기 어려워집니다. 새 두 테이블에 **수정한 부모 5개·그림 연결 8개·새 청크 28개**만 저장합니다.

- `review_revisions`: 원본 버전, 수정 부모와 그림 ID 참조, 내용 식별값, 검토·모델 설정.
- `review_revision_chunks`: 새 청크의 글·출처와 로컬 768차원/OpenAI 1536차원 벡터.
- 검색할 때 이 다섯 부모의 이전 청크만 대체합니다. 다른 부모·기존 벡터·그림 파일은 재사용합니다.
- 활성 버전은 지정한 ID·내용 식별값으로 조회합니다. 저장 완료와 새 연결 대조 후에만 활성화합니다.
- 그림 픽셀은 임베딩하지 않습니다. 본문과 확인한 그림 설명을 임베딩합니다.

28개 청크의 OpenAI 입력은 5,533토큰, 문서 임베딩 배치 1회입니다. 로컬 모델도 같은 새 입력 28개로 계산했습니다. 새 자료의 수치·경고·단위는 전체 부모로 연결해 읽습니다.

저장 전 첫 확인은 17/18이었고, 스위치가 무엇을 선택하는지 묻는 표현까지 보완해 두 번째 확인은 18/18, 로컬 진단 3/3이었습니다. 첫 확인의 생성 2건은 총 2,196토큰을 사용했습니다. 두 번째 확인은 같은 질문 벡터 17개와 동일 근거의 생성 결과를 재사용했으며 새 생성·질문 임베딩 API 호출이 없습니다. 첫 결과를 덮어쓰거나 생성 재사용을 새 호출로 세지 않았습니다.

최신 main 공통 세션이 `full_vector_sql` 인자를 추가한 변경도 확인했습니다. 개인 SQL 로그 함수만 호환되도록 보완하고 기존 자료 읽기 전용 조회를 확인했습니다. 팀 공통 코드를 직접 수정하지 않았습니다.

원래 DB는 검토 부모 20개와 초안 507개를 보존합니다. 수정 버전 적용 시 검색에는 검토 부모 25개와 초안 502개가 사용됩니다. 기존 테이블의 상태를 몰래 승격하는 방식이 아닙니다.

## 5. 결과 확인 방법

먼저 [31번 노트북](../../../notebooks/31_post_refactor_results.ipynb)을 순서대로 실행하세요. 저장 결과만 읽으며 임베딩·DB·생성 API를 실행하지 않습니다.

- 수정 전 결과: `sequence_summary_20261005.json` 및 개인 reports의 `sequence_20261005_172146/`.
- 저장 전 확인: 개인 data의 `review_revisions/preflight_20261006.json`.
- DB 저장 후 대조: 같은 폴더의 `db_saved_20261006.json`, `readback_search_20261006.json`.
- 공유할 최종 개요: `review_revision_summary_20261006.json`.

실행 자료·벡터·개인 활성 선택 파일은 Git에 넣지 않습니다. 공유하는 `review_revision_selection.json`은 저장 완료한 버전 ID·내용 식별값만 담습니다. 개인 선택 파일이 없으면 이 공유 선택을 사용하고, 해당 DB·상태·식별값이 다르면 중단합니다. 팀원 코드·공통 설정·다른 스키마에 쓰지 않습니다. [노션에 추가할 문안](./notion_update_draft.md)은 초안이며 이번 작업에서 노션 본문을 직접 수정하지 않습니다.

### 실제 DB 반영 완료 — 2026-10-06

개인 변경을 `bb6d37a`로 main에 먼저 푸시한 뒤 Supabase 개인 스키마에 저장했습니다. 부모 5개·새 청크 28개·그림 연결 8개가 저장 완료 상태이며, 기존 개인 여덟 테이블의 행 수와 내용 식별값은 전후 동일했습니다. 새 연결로 읽은 두 모델 벡터도 준비한 값과 float32 기준으로 일치했습니다.

이전 청크 25개를 검색에서 새 청크 28개로 대체해 현재 검색용 청크는 **2,216개**입니다. 부모는 527개이며, 원본 화면 대조한 부모 25개·남은 자동 초안 502개를 구분합니다. 그림 파일은 기존 864개를 재사용하며 이번 추가 업로드는 없습니다.

|---|---:|---:|
| 새 검토 두 테이블 | 540,672 | 0.54 |

Storage 값은 기존 전체 파일 업로드 확인의 바이트 합계입니다. 이번에는 Storage 파일을 다시 조회·변경하지 않았습니다. WAL·공통 영역·다른 팀원 자료·서비스 청구량은 포함하지 않습니다.

저장 후 세 질문은 모두 지정한 수정 버전에서 실제 근거를 읽었습니다. 지문 인증 번호는 차량 내부 I, 테일게이트 설정은 작동·중지·감지 영역, 버튼 번호는 기능 중지 자료를 연결했습니다. [DBeaver 조회 SQL](./db/09_inspect_review_revisions.sql.txt)의 네 SELECT도 개인 DB 읽기 전용 연결에서 확인했습니다. DBeaver에서는 연결 → Schemas → `zzong_santafe_lag` → Tables를 새로고침해 `review_revisions`와 `review_revision_chunks`를 보세요. 제목과 전체 글은 첫 테이블의 `payload`에 있어 두 번째 SELECT가 읽기 편합니다.

화면 생성에서 감지 영역 출처 [3]을 빠뜨려 발췌로 돌아간 결과도 보존했습니다. 필수 자료별 관련 조건·주의사항을 포함하라는 프롬프트를 추가한 뒤 같은 근거의 재생성은 [1]·[2]·[3] 검사를 통과했습니다. 출처 검사 기준은 완화하지 않았습니다. 모델이 text와 citation_ids 양쪽에 번호를 써 생긴 중복 표시도 문장 끝의 동일 표지만 정리합니다. 관련 없는 번호나 [경고] 표시는 지우지 않습니다.

프롬프트의 명확한 지시와 실제 응답 비교는 [OpenAI 공식 가이드](https://developers.openai.com/api/docs/guides/prompt-engineering)를 참고했습니다. 생성 성공은 출처·형식 검사 통과이며 모든 조건의 의미 정확도나 독립 평가 완료를 뜻하지 않습니다. 이번 18문항은 보완에 사용한 회귀 확인입니다.

보완 코드를 개인 화면 서버에 다시 반영한 최종 브라우저 검색·생성도 완료했습니다. 실제 화면은 세 출처를 표시하고 중복 번호가 없었으며, 관련 그림 세 파일의 실제 로딩을 확인했습니다. 최초 화면 보류 2,798토큰 → 같은 근거 Python 재생성 3,390토큰 → 최종 화면 생성 3,112토큰을 모두 보존했습니다. 이 세 호출의 합은 9,300토큰이며 저장 전 생성 2건 2,196토큰과 구분합니다. 문법·JSON·5개 노트북 구조도 확인했습니다.

상세 수치는 [최종 공유 요약](./review_revision_summary_20261006.json), 화면 증거는 개인 `data/zzong_santafe_lag/reports/review_revision_ui_answer_20261006.png`와 `review_revision_ui_images_20261006.png`에 있습니다. 큰 개인 실행 결과·화면 파일은 로컬에 보관하고 최종 공유 요약만 Git에 넣습니다.
