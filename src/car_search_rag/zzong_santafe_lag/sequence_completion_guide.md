# 10월 5~6일 확인 결과와 원문 보완

## 이번 순서

1. 코드 정리 후 서버를 재시작해 화면의 검색·답변·그림·보류를 확인했습니다.
2. 실외 미러와 스마트 테일게이트의 원본 화면을 대조하고 수정안을 준비했습니다.
3. 새로운 표현으로 검색을 평가해 약한 부분을 찾고 질문 목적 규칙을 보완했습니다.
4. 수정 자료의 청킹·두 모델 임베딩·저장 전 확인을 거쳐 개인 DB에 별도 버전으로 저장합니다.

## 1. 어제 실제 화면에서 확인한 내용

| 질문 | 관찰 결과 |
|---|---|
| 차대번호 위치 그림 | PDF 45쪽 근거로 답변 생성, 관련 그림 탭에서 실제 그림 표시 |
| 오일 교체량과 SAE 점도 | 표·각주를 연결해 답변 생성 |
| 주행 중 좌석·휠·미러 조절 | PDF 53쪽의 금지 지침으로 답변 생성 |
| 내 차의 현재 리콜 대상 여부 | PDF 밖 질문으로 보류, 생성 호출 없음 |
| 스마트 테일게이트 설정 | 당시 미검토 자료여서 보류, 생성 호출 없음 |

다섯 조건이 일치했습니다. 생성 3회·3,910토큰, 질문 임베딩 입력 5개입니다. 전체 답변 정확도나 모든 그림의 확인 완료를 뜻하지 않습니다. 스마트 테일게이트의 보류 결과는 **검토 수정 버전을 적용하기 전**의 기록입니다.

## 2. 새 표현에서 발견한 문제

| 질문 | 수정 전 근거 선택 | 원인과 보완 |
|---|---|---|
| 차량 내부 I 그림에서 지문 인증 기능에 붙은 번호 | 차대번호 자료 | 그림 번호 표현을 기능 설명으로 분류했고, '번호'의 단어 일치가 다른 자료를 허용했습니다. 그림 번호의 목적을 구별하고 일반 단어를 근거 선택 단어에서 제외했습니다. |
| 스티어링 휠과 미러 위치는 출발 전에 맞추나요 | 위치 안내도 | '위치'만 보고 안내도를 우선했습니다. 조절할 시점을 묻는 표현은 조작 지침을 찾도록 했습니다. |

`question_intent.py`에서 검색과 답변 선택이 같은 작은 한국어 규칙을 사용합니다. 질문별 정답·쪽수·ID를 운영 검색에 넣지 않았습니다. 규칙 방식의 한계가 있으므로 모든 한국어 표현에 대한 의미 판정으로 설명하지 않습니다.

수정 전 OpenAI 10문항의 기대 ID Hit@5는 80%, MRR@5는 0.62입니다. 후보 내용을 대조한 잠정 Hit@5는 80%, MRR@5는 0.72이며, Precision@5는 **22~24%**입니다. 50개 후보 중 직접 관련 11개, 경계 사례 1개를 따로 남겼습니다. 클러스터 질문의 일반 연료 점검 표를 관련으로 볼지는 사람 판정이 필요합니다.

이 평가의 문항은 확인한 일부 주제의 새 표현입니다. 이전 10문항의 36%와 문항이 달라 성능이 하락했다고 단정할 수 없습니다. 로컬은 3문항만 진단했으므로 모델 간 우위 비교에 쓰지 않습니다. 생성 API를 호출하지 않은 이 10문항의 결과를 생성 답변 정확도로 표시하지 않습니다.

## 3. 원문을 보고 보완한 자료

| 스마트 테일게이트 개요·작동·중지·감지 영역 | 275~278쪽 | 스마트 키 버튼 번호 1~4 복원, 설정/조건/주의사항/중지/감지의 연결 |
| 그림 8개 | 위 원본의 그림 | 그림 아래 소제목과 연결하고 검색용 설명 추가 |

작동 설명에 같은 페이지라는 이유로 붙은 그림 2개 연결을 수정 버전에서 제외했습니다. 개요의 접근 그림과 기능 중지의 키 그림은 각각 해당 소제목에 연결합니다. 파일을 삭제하거나 재업로드하지 않습니다. 보존 원문 `raw_text`는 그대로입니다.

검토는 Codex의 원본 화면 대조입니다. 사람 교차 검토 완료로 표시하지 않습니다. 원본에 실제로 표시된 주의사항은 차량 사양을 추측해 삭제하지 않았습니다.

## 4. DB 저장 구조를 왜 추가하나요?

기존 부모 527개·청크 2,213개·그림 864개를 다시 복제하면 용량이 늘고 이전 실험을 재현하기 어려워집니다. 새 두 테이블에 **수정한 부모 5개·그림 연결 8개·새 청크 28개**만 저장합니다.

- `review_revisions`: 원본 버전, 수정 부모와 그림 ID 참조, 내용 식별값, 검토·모델 설정.
- `review_revision_chunks`: 새 청크의 글·출처와 로컬 768차원/OpenAI 1536차원 벡터.
- 검색할 때 이 다섯 부모의 이전 청크만 대체합니다. 다른 부모·기존 벡터·그림 파일은 재사용합니다.
- 활성 버전은 지정한 ID·내용 식별값으로 조회합니다. 저장 완료와 새 연결 대조 후에만 활성화합니다.
- 그림 픽셀은 임베딩하지 않습니다. 본문과 확인한 그림 설명을 임베딩합니다.

28개 청크의 OpenAI 입력은 5,533토큰, 문서 임베딩 배치 1회입니다. 로컬 모델도 같은 새 입력 28개로 계산했습니다. 새 자료의 수치·경고·단위는 전체 부모로 연결해 읽습니다.

저장 전 첫 확인은 17/18이었고, 스위치가 무엇을 선택하는지 묻는 표현까지 보완해 두 번째 확인은 18/18, 로컬 진단 3/3이었습니다. 첫 확인의 생성 2건은 총 2,196토큰을 사용했습니다. 두 번째 확인은 같은 질문 벡터 17개와 동일 근거의 생성 결과를 재사용했으며 새 생성·질문 임베딩 API 호출이 없습니다. 첫 결과를 덮어쓰거나 생성 재사용을 새 호출로 세지 않았습니다.

최신 main 공통 세션이 `full_vector_sql` 인자를 추가한 변경도 확인했습니다. 개인 SQL 로그 함수만 호환되도록 보완하고 기존 자료 읽기 전용 조회를 확인했습니다. 팀 공통 코드를 직접 수정하지 않았습니다.

원래 DB는 검토 부모 20개와 초안 507개를 보존합니다. 수정 버전 적용 시 검색에는 검토 부모 25개와 초안 502개가 사용됩니다. 기존 테이블의 상태를 몰래 승격하는 방식이 아닙니다.
