검색과 등록의 흐름
================================

**검색은 관련 내용을 읽는 작업, 등록은 검색할 자료를 준비하는 작업입니다.**

질문을 검색할 때
------------------------------

.. container:: flow

   **질문** → **질문 임베딩** → **DB 유사도 검색** → **관련 페이지**

1. ``search_machine_manual()`` 에 브랜드, 모델명, 질문을 전달합니다.
2. ``embed_query()`` 가 질문을 숫자 목록으로 바꿉니다.
3. SQL이 같은 브랜드·모델의 매뉴얼에서 의미가 가까운 내용을 찾습니다.
4. 최대 ``limit`` 건의 페이지·텍스트·유사도를 반환합니다. 기본값은 5입니다.

SQL은 벡터 사이의 코사인 거리가 작은 순서로 결과를 정렬합니다.
``SIMILARITY`` 는 ``1 - 거리`` 이며, 정답 확률을 뜻하지 않습니다.
검색은 매뉴얼 데이터를 변경하지 않지만 외부 임베딩 API를 호출합니다.

PDF를 등록할 때
------------------------------

.. container:: flow

   **PDF 읽기** → **한국어 추출** → **문서 임베딩** → **DB 저장**

1. ``DocumentReader`` 가 페이지별 텍스트와 페이지 번호를 읽습니다.
2. ``pdf_filter()`` 가 ``KR`` 표시 뒤의 한국어 구간을 추출합니다. 모든 PDF에 통하는 필터는 아닙니다.
3. ``insert_pdf_docs()`` 가 ``embed_documents()`` 로 텍스트를 벡터로 바꿉니다.
4. 트랜잭션 안에서 머신을 조회·등록하고 상세 페이지 데이터를 교체합니다.

.. warning::

   **재등록하면 해당 머신의 기존 상세 데이터가 삭제되고 다시 저장됩니다.**
   대상 브랜드·모델과 입력 PDF를 먼저 확인하세요. 기본 실행 파일의 PDF 등록 호출은 주석 처리되어 있습니다.

임베딩은 DB 트랜잭션 전에 실행됩니다. 이 API 호출이 실패하면 DB 변경을 시작하지 않습니다.
DB 변경 중 예외가 전파되면 트랜잭션이 변경을 취소합니다.
현재 임베딩 모델 상수는 ``text-embedding-3-small`` 입니다.
등록과 검색에 사용하는 모델과 벡터 차원을 맞춰야 합니다.

어떤 코드가 무엇을 맡나요?
--------------------------------

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 구성 요소
     - 역할
   * - 실행 파일
     - 입력을 정하고 서비스를 호출
   * - ``CoffeeSearchService``
     - 필터 → 임베딩 → DB 작업의 순서를 관리
   * - ``DocumentReader``
     - PDF에서 페이지별 텍스트 추출
   * - ``SqlSession``
     - 이름으로 SQL 호출, 연결과 트랜잭션 관리
   * - ``DatabaseManager``
     - PostgreSQL 연결과 벡터 타입 등록
   * - ``coffee_search.sql``
     - 조회·등록·삭제·유사도 비교 SQL 정의

현재 실행 파일의 추가 동작
--------------------------------

``coffee_search.py`` 는 파일 하단에서 검색을 실행한 뒤 ``StorageManager`` 를 생성하고
로컬 이미지를 Supabase에 업로드합니다. import만 해도 이 코드가 실행될 수 있습니다.
문서 빌드는 이 파일을 import하지 않습니다. 검색만 하려면 :doc:`getting_started` 를 사용하세요.
