설정과 비밀값 보호
==============================

**문서에는 설정의 이름만 적고, 실제 값은 로컬에 보관합니다.**

공유해도 되는 것과 빼야 하는 것
----------------------------------------

.. list-table::
   :header-rows: 1
   :widths: 35 65

   * - 문서에 필요한 정보
     - 공유에서 제외할 정보
   * - ``DB_URL`` 이라는 설정 이름
     - 실제 DB 주소, 계정, 비밀번호, 전체 연결 문자열
   * - ``OPENAI_API_KEY`` 의 용도
     - 실제 API 키와 Authorization 헤더
   * - 이미지 저장소 연동 방법
     - 실제 ``SUPABASE_URL``, ``SUPABASE_SECRET_KEY`` 값
   * - 가상의 검색 예제와 결과 건수
     - 비공개 문서 원문, 개인정보, 내부 결과 화면

로컬 .env를 쓴다면
------------------------------

저장소의 ``.gitignore`` 에 아래 규칙을 넣고 제외 여부를 확인하세요.

.. code-block:: text

   .env
   .env.*
   !.env.example

.. code-block:: console

   git check-ignore .env
   git ls-files -- .env '.env.*'

첫 명령은 제외 규칙 적용 여부를 확인합니다. 두 번째 명령에 실제 설정 파일이 나타나면
이미 추적 중일 수 있습니다. ``.gitignore`` 추가만으로 기존 추적이나 커밋 기록이 없어지지는 않습니다.
``.env.example`` 에도 실제 값을 넣지 마세요.

문서 빌드에서 지키는 범위
--------------------------------

* 애플리케이션 모듈을 import하거나 ``.env`` 를 읽지 않습니다.
* 소스 코드 원본과 설정 파일을 HTML에 복사하지 않습니다.
* 정적 자산은 검토 가능한 CSS 한 파일만 사용합니다. 과거 구조 그림과 캡처는 배포에서 제외합니다.
* 키·토큰·인증정보가 들어간 URL의 대표 패턴을 원본과 빌드 결과에서 검사합니다.
* 검사 실패 시 값 자체를 출력하지 않고 파일명과 탐지 종류만 표시합니다.

패턴 검사는 모든 비밀값을 식별하지 못합니다. 새 텍스트나 자산을 추가할 때는 별도 검토가 필요합니다.
이 문서의 보호 조치는 애플리케이션 전체의 로그 마스킹을 대신하지 않습니다.

이미 값이 공유되었다면
------------------------------

노출된 키는 제공 서비스에서 폐기·재발급하고, DB 자격증명은 교체하세요.
공개 문서와 로그에서 값을 제거한 뒤 공유·배포 이력도 확인하세요.
