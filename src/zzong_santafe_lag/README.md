### 개인 실험 환경 준비

팀 공통 `pyproject.toml`과 `uv.lock`을 보존하기 위해 개인 패키지는 이 폴더의 `requirements.txt`로 관리합니다. 처음 실행할 때 프로젝트 루트에서 아래 두 명령을 차례로 실행합니다.

```powershell
uv venv --python 3.12 src/zzong_santafe_lag/.venv
uv pip install --python src/zzong_santafe_lag/.venv/Scripts/python.exe -r src/zzong_santafe_lag/requirements.txt
```

아래 실행 예시의 `.\.venv\Scripts\python.exe`는 기존 실험 환경입니다. 새 개인 환경을 준비했다면 `.\src\zzong_santafe_lag\.venv\Scripts\python.exe`로 바꾸어 실행합니다. VS Code 노트북에서도 이 개인 환경을 커널로 선택합니다. 원본 PDF와 모델 캐시는 별도로 준비해야 합니다.

`data/zzong_santafe_lag/sung/`은 별도의 캐스퍼 참고 앱이며 자체 `pyproject.toml`과 실행 안내를 사용합니다.

프로젝트 폴더 `C:\mle-02-p1-team1`의 VS Code 터미널에서 아래 명령을 실행합니다.

```powershell
.\.venv\Scripts\python.exe .\src\zzong_santafe_lag\manual.py preview
```

현재 PDF 기준 예상 결과는 **779쪽, 이미지 참조 864개, 부모 원문 527개, 검색 조각 2,213개**입니다. 실제 모델 입력은 최대 128토큰입니다. 토큰은 모델이 글을 읽는 작은 단위로, 글자 수와 다릅니다.

`preview`는 PDF를 읽고 청크를 만듭니다. 로컬 토크나이저(토큰을 세는 도구)는 사용하지만 임베딩 계산은 하지 않습니다. 데이터·이미지·벡터 파일과 DB에는 저장하지 않습니다.

## 노트북에서 Python 파일로 바뀌는 점

노트북은 셀을 하나씩 실행하면서 결과를 확인하는 실험 기록입니다. Python 파일은 확인한 작업을 함수로 묶어 같은 순서로 다시 실행하는 프로그램입니다.

예를 들어 노트북의 “PDF 읽기” 셀은 `pdf_reader.py`의 `inspect_pdf()` 함수가 되었습니다. 함수는 입력을 받아 정해진 일을 한 뒤 결과를 돌려주는 작은 작업 묶음입니다.

**처리 순서:** PDF 읽기 → 주제별 원문 묶기 → 확인한 표 보완 → 작은 청크 만들기 → 임베딩 → 근거 검색.

전체 원문 묶음을 **부모 기록**, 검색하기 좋은 작은 조각을 **자식 청크**라고 부릅니다. 작은 청크로 찾은 뒤 답변에 필요한 원문·각주·주의사항은 부모 기록에서 읽습니다.

## 읽어 볼 파일 순서

| 파일 | 역할 |
| --- | --- |
| `manual.py` | 시작 파일. 미리보기·검색·기존 질문 비교 중 무엇을 할지 받습니다. |
| `manual_service.py` | 위 처리 순서대로 함수를 호출합니다. 먼저 `prepare()`를 읽습니다. |
| `config.py` | PDF 경로와 모델·CPU 설정입니다. |
| `pdf_reader.py` | 페이지 글자, 목차, 인쇄 쪽수, 이미지 키를 읽습니다. |
| `sample_records.py` | 노트북에서 확인한 안내도와 본문 예제를 재현합니다. |
| `topics.py` | 목차 제목과 인쇄 쪽수로 전체 본문을 자동 주제 초안으로 묶습니다. |
| `reviews.py` | 화면에서 대조한 오일 표·패들 기호·각주 관계를 보완합니다. |
| `chunking.py` | 실제 토큰 한도 안으로 나눕니다. 확인한 표는 행 관계를 유지합니다. |
| `embedding.py` | 설치된 한국어 모델로 청크를 768개 숫자로 바꿉니다. |
| `retrieval.py` | 의미 점수와 글자 점수를 결합하고 질문 목적에 맞는 자료를 찾습니다. |
| `evaluation.py` | 기존 30개 질문의 기대 출처와 검색 결과를 비교합니다. |
| `source_review.md` | 이번에 검토한 안전벨트 질문의 원본 근거와 남은 문제입니다. |

한 번에 모든 파일을 이해할 필요는 없습니다. 첫 실행 결과를 확인한 다음 `manual.py → manual_service.py → pdf_reader.py` 순서로 살펴보면 됩니다. 각 함수와 중요한 처리에 한국어 설명을 달았습니다.

## 검색 실험

```powershell
.\.venv\Scripts\python.exe .\src\zzong_santafe_lag\manual.py search --question "엔진 오일의 용량과 추천 사양을 알려줘."
```

처음에 전체 2,213개 청크를 CPU에서 임베딩하므로 시간이 걸립니다. 진행 개수와 예상 남은 시간을 표시합니다. 모델은 이미 다운로드한 `jhgan/ko-sroberta-multitask-mrl`을 로컬에서 읽습니다. 모델 캐시가 없으면 다운로드를 시도하지 않고 오류로 중단합니다.

같은 실행에서 여러 질문을 비교하려면 `--question`을 반복합니다. 청크 임베딩을 한 번만 계산합니다.

```powershell
.\.venv\Scripts\python.exe .\src\zzong_santafe_lag\manual.py search --question "안전벨트 버클을 얼마나 밀어 넣어야 하나요?" --question "차단 클립을 버클에 꽂으면 경고등과 경고음은 어떻게 되나요?"
```

표시되는 내용은 **검색 후보**입니다. 높은 점수는 정답 보장이 아닙니다. PDF 쪽수, 원문, 검토 상태를 함께 확인합니다. `--full-text`를 붙이면 연결 원문 전체를 표시합니다.

이미지는 페이지 번호와 이미지 키·설명·기존 로컬 경로를 연결합니다. 이 명령은 이미지를 새로 저장하거나 화면에 그림 자체를 표시하지 않습니다. 전체 864개 그림의 설명이 완성된 상태도 아닙니다. 자동 추출된 그림 연결은 페이지 수준 초안으로 표시합니다.

## 기존 실험 다시 비교하기

```powershell
.\.venv\Scripts\python.exe .\src\zzong_santafe_lag\manual.py evaluate
```

노트북 11~12번과 같은 질문 30개를 사용합니다.

| 방식 | 노트북의 첫 후보에 기대 출처가 있음 | 상위 3개에 기대 출처가 있음 |
| --- | --- | --- |
| 부모 전체 글자 색인 | 14/30 | 21/30 |
| 청크·안내도 항목 글자 색인 | 21/30 | 27/30 |
| 질문 목적별 후보 선택 | 26/30 | 28/30 |

이 수치는 **검색 출처 비교**이며, 챗봇 답변의 정확도나 모든 질문의 성능을 뜻하지 않습니다. 기대 출처는 평가 파일에만 있고 검색 순위를 만들 때 사용하지 않습니다. 안전벨트의 다른 유효한 근거는 별도 검토 기록에 남겨 비교 조건을 유지합니다.

## 저장 형식과 다음 단계

- 부모 기록: `content`(검색용 글), `raw_text`(보존 원문), `metadata`(출처·검토 상태), `image_parts`(그림 참조).
- 자식 청크: 부모 ID, 원문 검색 글에서의 구간, 실제 토큰 수, 출처·검토 상태를 포함합니다.
- 임베딩: 청크마다 768차원 벡터이며 현재는 실행 중 메모리에만 둡니다. 프로그램을 종료하면 사라지고 다음 실행에서 다시 계산합니다.
- 현재 527개 부모 중 14개는 확인한 예제, 6개는 원본 화면을 대조한 자료, 507개는 추가 검토할 자동 초안입니다.
- 답변 생성, 근거 부족 시 응답, Supabase 저장, 이미지 화면 출력은 다음 단계입니다.

SQL Mapper Documentation의 실행 파일 / 서비스 파일 구성을 따라 개인 실행 파일과 서비스 파일을 나눴습니다. 현재 공통 Mapper는 `car_search/*.sql`만 읽으므로 개인 폴더의 SQL은 자동으로 읽히지 않습니다. DB 단계에서 개인 `manual.sql` 위치와 등록 방법을 정하고, **내 전용 테이블·Storage 경로**만 사용하도록 설계합니다. 현재 DB 연결이나 SQL 실행 코드는 없습니다.
